## Classification: one shared class, plus adapter-specific materiality (Phase 1 answer)

Two distinct mechanisms, not one:

**Mechanism A — established-but-unrequired material modifier invisible in the decision** (limitation_of_liability's original 3 cases, ip_ownership-085/086, insurance-105/106, warranties-185): the deterministic layer correctly discovers and structures the primary fact AND the modifier, but the modifier only reaches the decision surface when a specific policy field explicitly names it. This occurs at stage **F (deterministic reconciliation) / G (policy evaluation)** in the taxonomy — never at grounding or admission.

**Mechanism B — cross-section/cross-clause reference never checked at all** (confidentiality-054/055/056, insurance-116, sla-214/216, assignment-236, and all 7 ARBITRARILY_SELECTED_COMPETING_READING cases): no mechanism exists to look BEYOND the local anchor window for a qualifying, contradicting, or ambiguity-declaring statement elsewhere in the document. This occurs at stage **E (adapter composition)** — the local window itself is correctly processed, but the document's full scope is never consulted.

Mechanism A was already solved once, for liability, by the immediately-prior mission (surfacing established-uncapped categories via `ACCEPT_WITH_NOTE`). This mission generalized it to insurance/warranties/ip_ownership using the SAME shared `detect_condition_in_span`/`detect_condition_in_text` primitives liability already used — not by inventing new per-adapter logic.

Mechanism B required a genuinely new set of shared primitives (`document_wide_conflict_detected`, `unreconciled_ambiguity_marker_present`, `cross_section_carveout_referencing`), built once in `policy_engine_core.py` and wired into 8 adapters (liability, insurance, sla, confidentiality, ip_ownership, payment_terms, assignment — data_security not touched, warranties partial).

Neither mechanism required weakening any existing deterministic gate, forcing every AI disagreement to `REQUIRES_REVIEW`, or adding case-ID-specific logic — every fix is a general structural/vocabulary pattern (a party role, a section-number cross-reference, a self-declared ambiguity marker), verified against fresh, non-burned-phrase test variants (see `tests/test_candidate3_zero_silent_loss.py`) and the full regression suite after every single change.
