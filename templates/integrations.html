Work where counsel already works

Word and Google Docs are thin clients over TriageCounsel APIs. Policy decisions still come from the deterministic engine — never from the add-in.

Microsoft Word

Sideload the Office Add-in manifest. The task pane extracts the open document, runs the selected playbook, shows findings, and can insert comments or apply a redline when the evidence excerpt is unique.

  1. Download the manifest
  2. In Word: Insert → Add-ins → Upload My Add-in
  3. Sign in from the task pane
  4. Choose a playbook and run review
Download Word manifest Open task pane (preview)

Host validation inside desktop Word is not claimed from this environment. The APIs the add-in calls are production-tested.

Google Docs

Same API as Word. Open the sidebar client, sign in, review the current document, inspect evidence, and insert comments. Suggested text is copied as a Docs suggestion when the Apps Script host supports it.

Open Google Docs sidebar client Apps Script source

Shared API

Both clients use bearer tokens against /api/v1. They do not embed the policy engine.

  • POST /api/v1/auth/login — issue a hashed token
  • GET /api/v1/playbooks — tenant playbooks
  • POST /api/v1/reviews — extract text, run the governed review
  • POST /api/v1/reviews/{id}/actions — accept / edit / reject
  • POST /api/v1/reviews/{id}/comments — record a comment (and whether it was inserted in the host)
  • POST /api/v1/reviews/{id}/reconfirm — invalidate stale decisions when the document changed
